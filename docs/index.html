Sift 模组开发文档

两个面向 Minecraft 26.3 / Fabric 的服务器配套模组：Sift Menu 把传送、经济、悬赏、队伍、邮箱收进 6×9 箱子菜单，并支持 JSON 自定义页面；Sift HUD 在按住 Tab 时显示在线、延迟、维度、金币与 TPS。本文档覆盖两者的实现原理、配置与二次开发。

Minecraft 26.3 Fabric Loader ≥ 0.19.5 Java 25 MIT License Sift Menu 1.22.1 Sift HUD 1.1.0

01项目概览

Sift Menu 最初是「筛界」整合包的服务器配套模组。服务端负责菜单逻辑、经济与数据持久化，客户端只负责按键、HUD 与少量渲染。模组本身不注册物品与方块，所有交互都通过原版箱子 GUI 与网络包完成。

菜单与传送家、死亡点、随机传送、玩家互传、主城大厅、精品传送点
经济系统全球市场（服务器买卖）、自由市场（玩家挂单）、金币与税收
玩法系统悬赏任务、头衔、邮箱补偿、Bingo 联动、小游戏入口
服务器治理大厅保护、区块清理、掉落物清理、睡眠跳过、兼容修复
统计板（Sift HUD）按住 Tab 显示在线、延迟、维度、金币与 TPS，H 键调整位置

02快速开始

服务器安装

  1. 把 siftmenu-1.22.1.jar 放进服务端 mods/。
  2. 确认已安装 fabric-api（26.3 版本）与 Fabric Loader ≥ 0.19.5。
  3. 启动服务器。模组会生成 config/siftmenu-data.json 与 config/siftmenu/menus.json。
  4. 服务器内执行 /siftmenu 打开主菜单；管理员执行 /siftmenu menu reload 重载自定义页面。

客户端安装

把同一个 jar 放进客户端 mods/ 即可。客户端提供：

  • G 键打开菜单（可在「按键设置」里改键）；
  • 悬赏 HUD 与点击跳转；
  • Bingo 胜利令牌的缓存与自动领取；
  • FTB Teams 界面跳转与队伍状态诊断。
服务端与客户端必须使用同一份 jar 模组声明了 "environment": "*"。只装服务端时菜单仍可使用，但 HUD、按键与 Bingo 领取等客户端功能不可用。

服务器配置

跨服地址与赞助链接不写死在代码里。首次启动会生成 config/siftmenu/config.json，默认全部留空：

{
  "schema": 1,
  "servers": {
    "main":    { "host": "", "port": 0 },
    "bingo":   { "host": "", "port": 0 },
    "bedwars": { "host": "", "port": 0 }
  },
  "sponsorUrl": ""
}
字段用途
servers.main「返回主服」与 Bingo 胜利奖励领取的目标服务器
servers.bingo小游戏页 Bingo 入口
servers.bedwars小游戏页起床战争入口
sponsorUrl主菜单「服务器赞助」按钮显示的链接；留空显示「准备中」
留空即禁用 未填写地址时，对应入口会提示「未配置」，不会连接到任何默认服务器。修改配置后重启服务器生效。

→

玩家点击时，原版会向服务端发送 ContainerInput。容器的 clicked() 只处理 0–53 号槽位：左/右键走 handleClick，Shift+点击走 handleShiftClick。两个方法都会先询问 CustomMenus.handleClick，未消费才进入内置页面的分支。

点击槽位slot 0–53
→
CustomMenus 优先自定义按钮 / 独立页面
→

→
业务方法传送、买卖、领取、翻页
→
setPage / 重新渲染broadcastChanges 同步客户端
为什么用箱子 GUI 原版 MenuType.GENERIC_9x6 自带客户端渲染、拖拽抑制与容器同步，服务端只需准备 54 个 ItemStack。因此模组不需要任何自定义 GUI 代码，也不依赖客户端安装才能打开菜单。

数据持久化

所有玩家数据集中保存在 config/siftmenu-data.json（MenuData 单例，get() 懒加载）。选型原因：服务器数据量小、便于备份与人工排查；读写都在服务端主线程，写入是「整文件覆盖」。

字段内容
homes / deaths按玩家 UUID 分组：家（最多 64，含公共/精品标记）、最近 5 次死亡点
balances / currencyVersion金币余额（内部「分」，1 金币 = 100 分），版本 2 起启用十进制
listings / pendingItems自由市场挂单、背包满时的待领取物品
sellAdmin / buyAdmin / removed*全球市场的管理员定价覆盖与下架列表
daily* / buy*每日产出/回收/税/挂单费统计，收购动态价格与 7 日成交量
titles玩家佩戴的头衔 id、自定义文本与颜色
mails / mailRead / mailClaimed公告与补偿邮件、阅读与领取记录
parties / playerParty / invites队伍、成员归属、待处理邀请
bountyBoard / bountyProgress当日悬赏板、玩家进度、每日接取计数
premiumContrib精品传送点的访客收益累计（按发布者封顶）

normalize() 负责字段补全，migrateCurrency() 负责旧存档的整数金币 → 分迁移（迁移前会写 siftmenu-data.pre-decimal.bak）。

网络包与事件

网络包方向用途
OpenMenuPayloadC → SG 键请求打开主菜单
OpenFtbPayloadS → C让客户端打开 FTB Teams 界面
BountyHudPayload / BountyHudClickPayloadS → C / C → S悬赏 HUD 内容与点击打开详情
BingoWinPayload / BingoClaimPayload / BingoClaimResultPayload双向胜利令牌下发、领取请求、结果回执
TeamStatusPayload / TeamResyncPayload双向队伍同步诊断与强制重同步

主要事件注册（SiftMenu.onInitialize）

  • CommandRegistrationCallback：/siftmenu 与 /siftmenu menu 命令树；
  • ServerLivingEntityEvents.AFTER_DEATH / ALLOW_DEATH：记录死亡点、鞘翅保留；
  • ServerPlayerEvents.COPY_FROM / AFTER_RESPAWN：跨维度保留数据并归还鞘翅；
  • ServerPlayConnectionEvents.JOIN / DISCONNECT：账号初始化、发菜单书、队伍诊断；
  • ServerTickEvents.END_SERVER_TICK：悬赏进度、HUD 推送、头衔刷新、清理任务；
  • UseItemCallback：右键「筛界菜单」书打开菜单；
  • ServerMessageEvents.ALLOW_CHAT_MESSAGE：聊天输入状态机拦截；
  • ServerLifecycleEvents.SERVER_STARTED：清理自由市场过期单、加载自定义菜单、固定 keepInventory；
  • ServerLifecycleEvents.SERVER_STOPPING：保存 MenuData。

04功能实现详解

4.1 菜单框架

页面枚举：MenuManager.Page 列出所有内置页面（MAIN、HOMES、DEATHS、RANDOM、PLAYERS、PARTY、GLOBAL_MARKET、FREE_MARKET、BOUNTY、TITLES、MAILBOX、ADMIN_* 等），新增的 CUSTOM 用于配置驱动的独立页面。

三个核心方法：

  • title(Page, pageIndex, customId)：把页面映射成标题（switch 表达式，必须穷举所有枚举值）；
  • build(container, player, page, pageIndex, category, customId)：按页面填充 54 个槽位。最后统一调用 CustomMenus.applyOverlay，所以自定义按钮可以覆盖同槽位的内置按钮；
  • handleClick(container, player, slot, rightClick)：处理点击。开头先交给 CustomMenus，再进入内置页面分支。

分页：列表类页面使用 pageIndex 与 setPage()；翻页会重新 fill()（铺灰色玻璃板）+ build() + broadcastChanges()。固定布局常量如 GRID_COLUMNS=7、PUBLIC_PER_PAGE=27 都在类顶部。

改动提示 往 Page 里加值会让 title() 的 switch 表达式失去穷举性而编译失败，这是刻意的：编译器会强制你补上标题，避免新页面显示空白。

4.2 家与传送点

家的数据：MenuData.Home 保存名称、坐标、朝向、维度、是否公共、是否精品、上架时间。每个玩家最多 64 个，名称不区分大小写去重；sift:lobby 维度禁止创建。

创建：菜单按钮记录当前位置，然后通过 ChatInput.requestHome 在聊天栏输入名称；聊天事件被拦截后写入 homes。

公共传送点：右键自己的家设为公共，公共点会出现在「世界传送」页（publicHomes()），床的图标变为青色并带附魔光效。公共点只允许主世界（unpublishPublicHomesOutside 可批量清理）。

精品传送点：只有公共点可以上架，全服 7 个槽位（主菜单 19–25）。上架 2000 金币、取消退 1000 金币；任何人传送一次，归属者得 100 金币；同一访客对同一发布者累计收益封顶 500 金币（premiumContrib 记录）。

冷却：家传送 3 分钟、公共点 3 分钟、随机传送 5 分钟、大厅 5 分钟；Bingo 服随机 10 分钟、玩家传送 5 分钟。冷却表是 Map<UUID, Long>，重启即清空。

4.3 死亡地点

ServerLivingEntityEvents.AFTER_DEATH 在玩家死亡时把坐标、维度、时间写入 MenuData.deaths，保留最近 5 条。菜单页按时间倒序渲染，点击直接传送（无费用、无冷却）。死亡记录只有本人可见。

4.4 随机传送

randomTeleport 以玩家为中心在 ±5000 格内取随机 X/Z，用 Heightmap.Types.MOTION_BLOCKING_NO_LEAVES 找地表，拒绝液体与危险方块后落点。目的维度由 levelOf 决定；失败会重试若干次，仍失败则退回原坐标提示。

「主城大厅传送」会记录进入前的坐标（TeleportRequestManager.recordLobbyReturn），「离开主城大厅」时回到该点。

4.5 玩家之间传送

TeleportRequestManager 维护待处理请求（按目标玩家 UUID）。左键是「我过去」，右键是「你过来」。请求以聊天可点击按钮（/siftmenu teleport accept|deny <player>）或菜单操作确认，双方同意后才执行 teleportTo。请求有过期时间，接受后立即移除，避免重复传送。

4.6 队伍

PartyManager 负责邀请、接受、拒绝、踢人、转让队长、退出、解散与 PvP 开关；MenuData.Party 存成员列表、队长与创建时间，playerParty 维护玩家 → 队伍索引。队伍界面把「成员管理」交给 FTB Teams：服务端关闭当前容器后发送 OpenFtbPayload("teams")，客户端调用 FTB Teams 的 OpenGUIMessage。PvP 开关通过队伍分数板队伍（scoreboard team）设置友伤规则。

4.7 全球经济（服务器买卖）

默认目录：只内置原版物品示例（种子、作物、畜牧产品、建筑方块、矿物与基础资源），开箱即用；不再包含任何模组或服务器专属条目。管理员可以在后台按物品 ID 添加条目并设置价格与额度。

价格：每个收购项有基础价与每日额度（全服 + 个人）。实际收购价 = 基础价 × 市场压力 × 7 日成交量修正；集中抛售会压低价格，停止抛售后约 8 小时恢复六成（buyPressure / buyVolume7d）。

交易：购买直接从市场扣款并给物品；收购从背包扣除物品并加钱，同时写 dailySold、dailySpent、dailyTax 等统计。每日 0 点 MenuData.dailyReset() 清空额度并结算。

管理员：后台 26 号位经济面板展示总金币、今日产出/回收/税收/挂单费、有效挂单；可增删物品、改价格与额度（sellAdmin / buyAdmin / removedSell / removedBuy）。

4.8 自由市场（玩家挂单）

规则数值 / 实现
挂单费10.00 金币/单，发布即扣，不退还
成交税5%，单笔总价低于 200.00 金币免税，从卖家所得扣除
挂单时长7 天，过期由 cleanup() 清理
数量上限出售 576，收购 64000；单价上限 100000.00 金币
收购托管发布收购时冻结 单价 × 数量，成交后释放给卖家
背包满物品进入 pendingItems，在「待领取物品」页领取

挂单用 MenuData.MarketListing 持久化（含物品 NBT 字符串、数量、单价、创建/过期时间）。购买时先校验余量、再扣款、再发货；收购成交时从卖家背包扣除物品并支付托管金币。所有失败路径都会给出明确聊天提示。

4.9 悬赏任务

悬赏定义：BountyCatalog 内置任务池（采集、击杀、探索、进度类），包含难度、目标、奖励与是否为「极限」。每天 0 点 ensureBoard 从池中抽取 56 个生成当日悬赏板。

接取限制：每人每天最多 5 个，其中极限悬赏最多 2 个（bountyDailyCount / bountyDailyExtreme）。

进度：BountyService.tick 与 tickAdvancements 周期性检查击杀、成就、统计与位置；进度写入 bountyProgress。完成目标后在菜单里点击领取，金币直接入账。

HUD：服务端每 tick 组装 BountyHudPayload（最多若干条进行中任务），客户端 BountyHudPanel 渲染在屏幕右侧并支持点击打开详情。

4.10 头衔系统

Titles.DEFS 是静态头衔表：id、显示名、颜色、解锁成就、说明、是否自定义。解锁条件是原版进度（unlocked() 检查 ServerPlayer.getAdvancements()）；自定义文本限制 1–12 字符，颜色支持 purple / blue / rainbow / red（红色仅管理员）。

佩戴后通过分数板队伍前缀显示在聊天与头顶：refreshName() 在登录与切换头衔时重建队伍，tickNames() 周期性刷新彩虹色。菜单里可预览、佩戴、清除与修改颜色。

4.11 邮箱与补偿

Mailbox 支持两类邮件：

  • 公告：发送给全服或指定玩家，纯文本；
  • 补偿：附带物品（支持多个），玩家点击领取后进入背包，背包满则进入待领取列表。

每封邮件有 id、标题、正文、发送者、创建时间、收件人列表（UUID 与名字快照）。mailRead / mailClaimed 按玩家记录，主菜单「邮箱」显示未读/未领取数量。管理员命令：/siftmenu mail announce <文本> 与 /siftmenu mail compensate <物品> <数量>，发送前会校验物品与权限。

4.12 Bingo 联动

模组通过 FabricLoader.isModLoaded 判断是否为 Bingo 服（同时要求服务端环境）。BingoHook 用 Class.forName 反射订阅 Bingo 的 BingoEvents，避免在普通服加载 Bingo 类导致崩溃；对局结束时按队伍分数判定名次，记录胜者。

胜者获得 1000 金币，但金币属于主服：BingoReward 生成带 HMAC 签名的令牌，经 BingoWinPayload 下发给客户端缓存；玩家转回主服后客户端自动发送 BingoClaimPayload，主服验签并按令牌去重发奖（bingoClaims）。

4.13 聊天输入

原版箱子界面无法输入文字，因此 ChatInput 用「挂起任务」模式：菜单点击时记录 Pending(type, key, itemData)，关闭容器并提示玩家在聊天栏输入；ServerMessageEvents.ALLOW_CHAT_MESSAGE 拦截下一条消息，解析成功后执行对应操作（创建家、队伍名、挂单价格/数量、头衔文本、公告、后台改价等），失败会提示并允许重试；输入 cancel 可取消。

4.14 主城大厅

大厅是独立维度 sift:lobby。三个守卫类分别处理：

  • LobbyBuildGuard：阻止放置/破坏方块与容器交互（带冷却提示，避免刷屏）；
  • LobbyMobGuard：实体进入大厅时清除或阻止生成；
  • LobbySpawnGuard：把误入大厅边界的玩家拉回安全点；
  • LobbyTimeSync：把大厅世界时钟同步为固定时间，保证永远是白天/固定氛围。

4.15 性能与维护

  • ChunkUnloadManager：周期性扫描被强制加载的区块票据，清理远离玩家且无意义的区块，降低内存与 tick 开销；
  • CleanupManager：定时清理掉落物并广播结果，防止实体堆积；
  • SleepSkip：统计睡觉人数，达到比例后直接跳到白天并广播；
  • AnvilUnseal：解除铁砧对「已封印/损坏」物品的限制（配合整合包机制）。

05自定义菜单（JSON 驱动）

这是 1.22.0 新增的能力：管理员可以只改 config/siftmenu/menus.json，就新增页面、修改按钮文案与图标、在内置页面上加按钮，并在不重启服务器的情况下热重载。

配置结构

文件位置：<服务端根目录>/config/siftmenu/menus.json。首次加载且文件不存在时，模组会自动生成空配置。

{
  "schema": 1,
  "pages": [
    {
      "id": "guide",                 // 必填：页面唯一 id
      "title": "&6服务器指南",        // 独立页面的标题（支持颜色代码）
      "base": "CUSTOM",              // CUSTOM = 独立页面；其他值 = 叠加到内置页
      "permission": "all",           // all | admin（整页权限）
      "allPages": false,             // 叠加时是否对所有分页生效
      "pageIndex": 0,                // 叠加到内置页的第几页（默认 0）
      "items": [
        {
          "slot": 13,                // 必填：0-53
          "item": "minecraft:diamond",
          "count": 1,                // 可选：1-64
          "name": "&b自定义按钮",
          "lore": ["&7第一行", "&7第二行"],
          "glint": true,             // 是否附魔光效
          "permission": "all",       // 单个按钮权限
          "pageIndex": 0,            // 可选：覆盖页面的 pageIndex
          "left":  { "type": "open", "page": "rules" },
          "right": { "type": "message", "text": "&a右键你好" }
        }
      ]
    }
  ]
}

顶层字段

字段类型说明
schemaint配置版本，当前为 1
pagesarray页面列表

页面字段

字段必填说明
id是唯一标识；独立页面可用 open 动作打开
title否标题，支持 &0–&f、&k–&o、&r
base否CUSTOM（默认）或内置页名：MAIN、HOMES、RANDOM、GLOBAL_MARKET 等
permission否admin 时整页仅管理员可见
allPages否叠加到分页页面时是否每页都显示

按钮字段

字段说明

type字段效果

独立页面的默认导航 独立页面会自动在 45 号槽放「返回主菜单」、49 号槽放「关闭」。如果配置里在同一槽位放了按钮，则以配置为准。

覆盖规则、权限与热重载

  1. 渲染顺序：先渲染内置页面，再叠加所有 base 相同的配置按钮。所以同槽位会覆盖内置按钮，点击时也会优先执行自定义动作。
  2. 分页：叠加默认只作用于第 0 页；需要每页都显示时设 "allPages": true。
  3. 权限：permission: "admin" 基于 COMMANDS_GAMEMASTER（OP 2 级）。管理员按钮对普通玩家完全不渲染；as: console 还会二次校验，防止提权。
  4. 校验与容错：缺 id、槽位越界、物品 id 无效、id 重复都会被跳过并写入日志；解析失败时继续使用上一份可用配置。
  5. 热重载：/siftmenu menu reload；/siftmenu menu list 查看已加载页面；/siftmenu menu open <id> 直接打开。

06二次开发指南

6.1 新增一个内置页面

  1. 在 MenuManager.Page 里加枚举值，例如 EVENTS。
  2. 在 title() 的 switch 里补 case EVENTS（否则编译失败）。
  3. 在 build() 的 switch 里补 case EVENTS:，用 button(...) / head(...) / marketItem(...) 放按钮。
  4. 在 handleClick() 里补点击逻辑；分页页面调用 setPage()。
  5. 在主菜单的 case MAIN 里加入口按钮。

6.2 新增一个点击行为

case EVENTS:
   switch (var2) {
      case 22 -> {
         var1.closeContainer();
         var0.setPage(0);        // 或执行传送、发消息等
      }
      case 45 -> open(var1, MenuManager.Page.MAIN, 0);
   }
   break;

注意：handleClick 的 var2 是槽位，var3 表示右键。所有修改须在主线程执行；异步任务请用 server.execute(...)。

6.3 新增持久化字段

  1. 在 MenuData 加字段（建议给默认值）。
  2. 在 normalize() 里补空值判断，兼容旧存档。
  3. 写操作后调用 save()；批量写时合并保存，避免频繁 IO。
  4. 如果涉及经济单位，遵循「内部用分、显示用金币」：读写都经过 Money / Economy。

6.4 新增网络包

  1. 新建 record，实现 CustomPacketPayload 与 StreamCodec（参考 BountyHudPayload）。
  2. 在 SiftMenu.onInitialize 里 PayloadTypeRegistry 注册，并注册接收器。
  3. 客户端在 SiftMenuClient.onInitializeClient 注册接收器，并用 client.execute(...) 切回客户端线程。
  4. 所有 ServerPlayer 操作都要在服务端线程执行。

6.5 扩展自定义菜单动作

在 CustomMenus.runAction 的 switch 里加分支，并在 ActionDef 加配置字段。例如新增 sound 动作：

case "sound" -> player.playNotifySound(
   BuiltInRegistries.SOUND_EVENT... , SoundSource.MASTER, 1f, 1f
);

同时更新 docs/index.html 的动作表，保持文档与代码一致。

6.6 代码约定

  • 包名固定 com.echoes.siftmenu；客户端代码放 client 子包。
  • 面向玩家的文本使用中文；日志使用 SiftMenu.LOGGER，前缀 [siftmenu]。
  • 不要硬引用可选模组的类；用 FabricLoader.isModLoaded + 反射（参考 BingoHook）。
  • 菜单里所有「可点击」的说明要写清楚左键 / 右键 / Shift 的行为。

10Sift HUD 概览

Sift HUD 是独立的统计板模组：服务端采集数据，客户端在按住 Tab 时把面板叠在原版玩家列表旁边。它与 Sift Menu 共用同一套网络包风格，但可以单独安装。

显示项数据来源
在线人数服务端玩家列表，客户端数据过期时回退到连接信息
延迟服务端主动探测的往返时间；无服务端数据时用客户端 PlayerInfo
当前维度客户端维度 id + 配置映射（原版三维度内置中文名）
全服金币 / 我的金币安装 Sift Menu 时通过反射读取 Economy，否则显示 0.00
TPS（1 / 5 / 15 秒）服务端 15 秒 tick 窗口计算

安装与使用

  1. 把 sifthud-1.1.0.jar 放进客户端与服务端的 mods/；
  2. 进入游戏，按住 Tab 显示统计板，松开隐藏；
  3. 按 H 打开位置编辑器，拖动面板后点击「保存并关闭」。
可独立运行 没有 Sift Menu 时，金币一栏固定为 0.00，其余数据正常；HUD 不会因为缺少经济模组而报错。客户端配置只影响渲染，服务端不需要读取 sifthud.json。

11HUD 数据流与实现

服务端 tickServerStats 记录 tick 时间
→
每 5 秒汇总TPS / 在线 / 上次延迟
→
StatsPayload下发给每个在线玩家
→
StatsPanel按住 Tab 时渲染

TPS 统计

ServerStats.tick 把每次服务端 tick 的 System.nanoTime() 放进 ArrayDeque，只保留最近 15 秒。计算时取窗口首尾的 tick 间隔求平均，再换算成 1000 / 平均间隔，上限 20；样本不足两个时按 20 处理。最终同时下发 1 秒、5 秒、15 秒三个窗口。

延迟探测

每 5 秒服务端给每个玩家发一条带自增 seq 的 PingProbePayload，客户端原样回 PingReplyPayload；服务端用发送时间与收到时间之差得到往返毫秒数，写入 PING_MS，随下一次 StatsPayload 下发。断线时清理该玩家的探测状态。

经济桥接

EconomyBridge 先判断 siftmenu 是否加载，再用反射调用 com.echoes.siftmenu.Economy.total() 与 balance(ServerPlayer)，把「分」原样放进 EconomyPayload；客户端显示时除以 100 并保留两位小数。反射失败只记录一次警告，HUD 继续工作。

客户端渲染

StatsPanel 通过 HudElementRegistry.attachElementAfter(VanillaHudElements.PLAYER_LIST, ...) 挂载，所以面板只在按住 Tab（原版玩家列表键）时出现，且不会与其他 HUD 抢位置。服务端数据超过 12 秒未更新时视为过期，在线与延迟回退到客户端连接信息。

网络包

网络包方向内容
StatsPayloadS → CTPS 1/5/15、在线人数、延迟（-1 表示未知）
EconomyPayloadS → C个人余额与全服总量（单位为分）
PingProbePayloadS → C探测序号
PingReplyPayloadC → S原样返回探测序号

12显示与配置

面板内容

面板固定 12 行、高度 140px，宽度按内容动态计算（最小 110px）。行结构由 StatsPanel.rows() 生成：标题、日期、分隔线、信息（在线 / 延迟 / 世界）、金币（全服 / 个人）、TPS（1 / 5 / 15 秒）、分隔线。

位置与编辑器

位置用 0–1 的相对坐标 statsX / statsY 保存，渲染时乘以「屏幕尺寸 − 面板尺寸」，因此换分辨率或 GUI 缩放后仍然贴边。默认 0.995 / 0.5（屏幕右侧中间）。按 H 打开 HudEditorScreen：左键拖动面板，点「保存并关闭」写入配置，「恢复默认」只重置位置。

config/sifthud.json

字段说明

title面板标题，默认「服务器状态」，最长 24 字符，留空回退默认
dimensionNames维度 id → 显示名；键可以是完整 id 或路径

14常见问题

改了 menus.json 没生效？

执行 /siftmenu menu reload；确认页面 id 唯一、按钮槽位在 0–53、物品 id 正确。重载失败时旧配置会继续生效，检查服务端日志里的 [siftmenu] 警告。

为什么自定义按钮点不动？

按钮需要配置 left 或 right 动作；只有 name/lore 的按钮是纯展示。若按钮是 admin 权限而你不是管理员，也点不到。

能用自定义页面替换市场列表吗？

不能。市场、悬赏、邮箱列表由代码动态生成；自定义页面适合公告、规则、导航、活动入口等静态内容。

服务器没有装 Bingo / FTB 会崩吗？

不会。Bingo 通过反射与 isModLoaded 检测；FTB Teams 相关代码在客户端点击队伍管理时才会用到，缺少模组时该入口不可用。

金币显示为什么有两位小数？

内部以「分」为整数存储（1 金币 = 100 分），显示与输入都按两位小数格式化，避免浮点误差。旧存档首次加载会自动 ×100 迁移。

如何只让管理员看到某个自定义页面？

页面设置 "permission": "admin"；按钮也可以单独设置。控制台身份执行命令的按钮必须有管理员权限。

按住 Tab 没有出现统计板？

确认客户端与服务端都安装了 Sift HUD，且没有改过原版「玩家列表」按键；服务端数据超过 12 秒未更新时面板仍会显示，但会回退到客户端在线/延迟数据。若装了其他 HUD 模组，检查是否被布局覆盖。

统计板金币一直是 0.00？

Sift HUD 通过反射读取 Sift Menu 的 Economy。未安装 Sift Menu、或经济桥接初始化失败时，金币固定为 0.00；查看客户端日志里是否有 [sifthud] 警告。

想改统计板标题或维度名？

编辑客户端 config/sifthud.json 的 title 与 dimensionNames，重进游戏生效；位置建议直接用 H 编辑器调整。
